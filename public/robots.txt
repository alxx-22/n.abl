# A disallow asks well-behaved crawlers not to fetch a URL. It does not hide
# anything from a person reading the HTML, and it is not access control — the
# internal surfaces are behind Supabase Auth and an access key, which is what
# actually protects them. This file is tidiness: an internal tool turning up in
# a search for the company name looks careless and advertises the surface.

User-agent: *

# Internal. Reachable from the footer's two unlabelled links, so crawlable
# without this.
Disallow: /team
Disallow: /crm
# The CRM's former path. It redirects to /crm now, but a crawler that already
# has the old URL should still be told not to fetch it.
Disallow: /sales-intelligence
Disallow: /portal

# Everything else is public: /, /privacy, /terms, /cookies
Allow: /

# AI crawlers are deliberately welcome, and deliberately NOT given their own
# groups.
#
# The decision first: GPTBot, ClaudeBot, PerplexityBot and the rest may read
# this site. Being quoted in an assistant's answer is a discovery channel a new
# business can actually win, unlike ranking, where nabl.org, nabl-agency.de and
# India's National Accreditation Board all outrank us for our own name. That is
# also why the public pages are rendered at build time — see
# scripts/build-routes.mjs. Blocking the crawlers and prerendering for them
# would be paying twice for nothing.
#
# Now the trap, which is why there is no "User-agent: GPTBot" block below.
# A crawler obeys the MOST SPECIFIC group that matches it and ignores the rest.
# So adding
#
#     User-agent: GPTBot
#     Allow: /
#
# would not add a permission to the rules above — it would replace them, and
# /crm, /team and /portal would be crawlable by that one agent. Any named group
# has to repeat every Disallow above, and the day someone adds a path here and
# not there is the day the CRM is indexed.
#
# One group, no exceptions, and the wildcard already covers them.

Sitemap: https://nabl.agency/sitemap.xml
